# 🕵️ Detective AI

OpenAI API와 Streamlit을 활용한 **대화형 추리 게임**입니다.

사용자는 탐정이 되어 사건 정보를 조사하고, 용의자의 진술과 알리바이, 시간 기록, CCTV, 현장 물증 등을 비교하면서 범인을 추리합니다.

단순히 AI에게 정답을 요청하는 방식이 아니라 `messages` 배열을 이용한 **Multi-turn Conversation(멀티턴 대화)**을 통해 이전 조사 내용을 기억하며 사건을 단계적으로 해결하도록 구현했습니다.

---

## 📌 프로젝트 개요

Detective AI는 LLM에게 **추리 게임 진행자(System Role)** 역할을 부여하고, 사용자가 자유롭게 질문하면서 사건을 조사하는 형태의 게임입니다.

사용자는 다음과 같은 정보를 직접 조사할 수 있습니다.

* 사건 발생 시간
* 사건 장소
* 용의자의 진술
* 용의자의 알리바이
* CCTV 및 출입 기록
* 현장에서 발견된 물증
* 시간대별 이동 기록
* 진술과 객관적 증거의 모순

충분한 정보를 확보한 뒤 범인을 추리하면 AI가 정답 여부를 판정합니다.

---

## 🎮 게임 진행 방식

```text
사건 브리핑 확인
        ↓
용의자 확인
        ↓
시간 / 장소 조사
        ↓
용의자 진술 확인
        ↓
알리바이 검증
        ↓
CCTV / 출입 기록 / 현장 물증 조사
        ↓
진술과 증거의 모순 발견
        ↓
단서 정리
        ↓
범인 추리
```

---

## 🗂️ 현재 구현된 사건

| 사건               | 용의자           |
| ---------------- | ------------- |
| 💎 사라진 다이아몬드     | 집사, 요리사, 정원사  |
| 🖼️ 박물관 그림 도난 사건 | 경비원, 관장, 청소부  |
| 📝 시험지 유출 사건     | 교사, 학생, 행정 직원 |
| 💍 호텔 보석 절도 사건   | 투숙객, 직원, 매니저  |

사이드바의 **`🔄 새로운 사건 시작`** 버튼을 누르면 현재 사건을 제외한 다른 사건이 랜덤으로 선택됩니다.

새로운 사건이 시작되면 기존 대화 기록도 초기화됩니다.

---

## 🔍 질문 예시

단순히 `"단서 알려 줘"`라고 질문하는 것뿐 아니라 여러 방향으로 사건을 조사할 수 있습니다.

```text
사건은 몇 시에 발생했어?

사건 장소는 어디야?

첫 번째 용의자는 뭐라고 진술했어?

그 사람의 알리바이를 확인해 줄 사람이 있어?

CCTV 기록이 있어?

현장에서 발견된 물건은 뭐야?

출입 기록을 확인할 수 있어?

그 사람의 진술과 기록이 충돌하는 부분이 있어?

지금까지 단서 정리해 줘.
```

## 🕵️ 범인 추리

범인을 충분히 추리했다면 다음과 같이 입력합니다.

```text
범인은 정원사다.
```

정답인 경우 AI가 사건 해결 여부와 근거를 알려 줍니다.

```text
정답입니다.

정원사는 저택에 들어가지 않았다고 주장했지만
서재에서 그의 장갑이 발견되었고,
현장의 흙자국도 그의 신발과 일치합니다.
```

정답을 맞히면 Streamlit의 `st.success()`와 `st.balloons()`를 이용해 사건 해결 효과가 표시됩니다.

## 🧠 System Prompt 설계

AI가 일반적인 챗봇처럼 행동하지 않고 **추리 게임 진행자 역할을 유지하도록 System Prompt에 게임 규칙을 정의했습니다.**

주요 규칙은 다음과 같습니다.

* 사용자는 탐정 역할을 수행합니다.
* AI는 사건의 전체 정보를 알고 있는 진행자 역할을 수행합니다.
* 사용자가 범인을 맞히기 전에는 범인을 직접 공개하지 않습니다.
* 질문과 관련된 단서를 단계적으로 제공합니다.
* 한 번의 질문에 지나치게 많은 핵심 단서를 제공하지 않습니다.
* 존재하지 않는 새로운 인물이나 증거를 임의로 생성하지 않습니다.
* `"단서 정리"` 요청 시 지금까지 공개된 정보만 정리합니다.
* 틀린 범인을 지목해도 정답을 공개하지 않습니다.
* 사건과 관계없는 질문은 제한합니다.

## 💬 Multi-turn Conversation

대화는 `messages` 배열에 계속 저장됩니다.

```python
messages = [
    {
        "role": "system",
        "content": "추리 게임 진행 규칙"
    },
    {
        "role": "user",
        "content": "사건은 몇 시에 발생했어?"
    },
    {
        "role": "assistant",
        "content": "사건은 저녁 8시 30분에서 9시 사이에 발생했습니다."
    }
]
```

새로운 질문을 할 때 이전 대화 전체가 다시 API에 전달되므로 AI는 지금까지 어떤 단서를 공개했는지 기억할 수 있습니다.

이를 통해 다음과 같은 대화가 가능합니다.

```text
사용자
정원사의 알리바이는?

AI
정원사는 정원 창고에서 도구를 정리했다고 주장했습니다.

사용자
그걸 확인해 줄 사람은 있어?

AI
정원사를 직접 봤다고 진술한 사람은 없습니다.

사용자
지금까지 정원사 관련 내용 정리해 줘.

AI
지금까지 확인된 정원사 관련 정보는...
```

## 🎲 Session State

Streamlit은 사용자 입력이 발생할 때마다 Python 파일을 다시 실행합니다.

따라서 현재 사건과 대화 내용을 유지하기 위해 `st.session_state`를 사용했습니다.

```python
st.session_state.case_index
```

현재 진행 중인 사건 번호를 저장합니다.

```python
st.session_state.messages
```

현재까지의 대화 기록을 저장합니다.

## 📖 핵심 학습 내용

이번 실습에서 확인한 핵심 개념은 다음과 같습니다.

### 1. System Prompt

AI의 역할과 행동 범위를 지정할 수 있습니다.

```text
일반 AI
→ 자유롭게 답변

추리 게임 System Prompt 적용
→ 사건 진행자 역할 유지
```

### 2. Messages

대화 내용을 배열 형태로 누적하여 LLM에 전달합니다.

```text
System
↓
User
↓
Assistant
↓
User
↓
Assistant
```

### 3. Multi-turn Conversation

이전 질문과 응답을 다시 전달하여 AI가 대화의 맥락을 유지할 수 있습니다.

### 4. Session State

Streamlit이 다시 실행되어도 현재 사건과 대화 기록을 유지합니다.

### 5. Prompt Engineering

단순히 `"범인을 알려 주지 마"`라고 지시하는 것을 넘어,

```text
역할 정의
→ 행동 제한
→ 단서 공개 규칙
→ 정답 판정 규칙
→ 예외 처리
```

형태로 프롬프트를 구체적으로 설계했습니다.
